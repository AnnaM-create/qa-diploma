# Перечень сценариев:
Позитивные (Оплата по карте): Ввести APPROVED карту (4444 4444 4444 4441). Проверить, что появилось сообщение об успехе, и в БД появилась запись со статусом APPROVED.
Позитивные (Кредит): То же самое, но кнопка "Купить в кредит".
Негативные (Оплата и кредит): Ввести DECLINED карту (4444 4444 4444 4442). Проверить сообщение об ошибке и запись в БД (DECLINED).
Негативные (пустые поля): Оставить все поля пустыми -> проверить сообщения об ошибках под каждым полем.
Негативные (неверный формат): Ввести невалидный месяц (например, 00), год (прошлый год), имя на русском, короткий CVC -> проверить сообщения.
Проверка граничных значений и сложной валидации: Валидация поля "Владелец" (длинные строки, спецсимволы, пробелы), поля "Год" (далекое будущее), поля "Месяц" (ввод одной цифры).
Проверка UI/UX взаимодействия: Проверка поведения формы при переключении между "Оплата по карте" и "Кредит" (очистка полей), проверка реакции на двойной клик по кнопке "Продолжить", корректное закрытие всплывающих уведомлений.
Проверка поддержки СУБД: Запуск автотестов с подключением к MySQL и PostgreSQL.

## Инструменты:
Selenide — чтобы легко работать с веб-элементами.
Faker — чтобы генерировать случайные имена и невалидные номера карт.
Lombok — чтобы не писать геттеры/сеттеры.
Gradle — для сборки и запуска.
Allure — для отчетов.
MySQL и PostgreSQL — для проверки баз данных.

### Риски: Эмулятор может не запуститься без Docker, база данных может не подключиться, приложение может падать (уронить SUT).
